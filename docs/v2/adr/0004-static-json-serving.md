# ADR-0004. 조회 API는 미리 계산한 정적 JSON으로 대신한다

- 상태: 제안 (2026-10-24)
- 결정: Spring 조회 API 응답과 같은 필드명의 JSON 파일을 집계 때 만들어 Pages에 올리고, React는 API 클라이언트 구현만 바꿔 읽는다.

## 배경

서버가 없으므로 요청마다 쿼리를 실행할 수 없다. 기존 React 화면과 테스트(52개)는 최대한 그대로 살리고 싶다.

## 검토한 대안

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| **정적 JSON (API 모양 그대로)** | 화면 수정 최소, CDN 캐시, 브라우저 부담 적음 | 매개변수가 있는 조회는 미리 만들 범위를 정해야 함 |
| 브라우저에서 DuckDB-WASM으로 Parquet 조회 | 임의 질의 가능 | 첫 로딩 수 MB, 모바일 성능, 화면 대수정 |
| 무료 호스팅에 Spring 유지 | v1 그대로 | ADR-0001의 서버 문제로 돌아감 |

## 결과

- 키워드 상세는 30일 기사 2건 이상이거나 목록에 나온 대표 키워드만 만든다(최대 3,000개). 색인에 없는 키워드는 "수집된 데이터 없음"으로 보인다. v1의 임의 키워드 검색은 지원하지 않는다.
- 두 키워드 비교·날짜별 근거는 키워드 파일 두 개로 브라우저에서 계산한다.
- 계약은 `contracts/site/*.schema.json`이고, CI가 생산(B)·소비(C) 양쪽을 같은 스키마로 검사한다.
